# 无限画布模块（PureRef 风格参考板）

第三个**专用视图**（前两个是待办、笔记）：`src/views/work/canvas/Index.vue`（薄壳两栏）+
`src/components/CanvasBoard/`（`CanvasSidebar` / `CanvasStage` / `CanvasItemView` / `CanvasToolbar` / `CanvasContextMenu`）+
`src/stores/canvas.ts`（数据、几何、撤销、自动保存）。路由 `/work/canvas`，菜单名「无限画布」。

一块画布 = 一份布局：能放**图片 / 文字便签 / 链接卡片 / 流程节点 / 分组框**，自由平移缩放、框选、拖动、等比缩放、旋转、裁剪、翻转、对齐吸附、层级调整，带撤销重做与自动保存；
元素之间可以**连线**（流程图），画布支持**全屏/专注模式**。

## 数据模型

- `work_canvas`：`title`、`theme`(dark/light)、`viewport`(json `{x,y,zoom}`)、`sort`、`trashed`、`trashed_at`。
- `work_canvas_item`：`canvas`(relation) + `kind`(image/text/link/frame/node/edge) + `oss_key`/`source_url` +
  几何（`x`/`y`/`w`/`h`/`rotation`/`z`）+ `crop`(json 归一化) + `flip_h`/`flip_v` + `color`/`text`/`font_size` +
  `frame_id`（所属分组框 id，空=顶层）+ `deleted`/`deleted_at` +
  连线专用 `from_id`/`to_id`（两端元素 id）/`from_anchor`/`to_anchor`/`edge_style`/`arrow`。

三个要点：

1. **坐标是世界坐标**，跟视图缩放无关；视口单独存在 `work_canvas.viewport`（`screen = world * zoom + x/y`）。
2. **分组框是容器**：子元素靠 `frame_id` 归属（不是靠几何包含），拖动框的标题栏会带上 `frame_id` 指向它的元素一起位移；
   缩放框时子元素同比例位移 + 缩放（文字项同步改 `font_size`）。拖动结束按「中心点落在哪个框里」重新归属，
   所以拖进/拖出框是自然发生的，不需要额外的挂载操作。不支持框套框。

3. **`kind` 是 select 字段，加类型要扩值**。`link`（链接卡片，见下面「粘贴链接」一节）就是 2026-10-14 加的第六种值；
   扩值由 `pnpm setup:pb` 幂等完成（`ensureCollection` 对 select 只做并集扩值）——**老库不跑一次脚本，前端发 `kind='link'` 会被 PB 400 掉**。
   前端 `normalizeItem()` 里也有一份 kind 白名单，漏了会把新类型静默当成 `image`。

## 流程图：流程节点 + 连线

- **流程节点**（`kind='node'`）＝ 圆角框 + 居中文字，工具栏「流程节点」创建并直接进入编辑。缩放手柄只改框大小、**不改字号**（流程图的框和字是两件事）。
- **连线**（`kind='edge'`）不存坐标，只存 `from_id`/`to_id`：端点每次渲染时从**元素当前外框**算出来，所以元素一移动线就跟着走，不需要同步逻辑。
  - 连接点自动取「两中心连线最短的一对边」（`autoSides()`）；也可以指定 `top/right/bottom/left`。
    连到旋转过的元素时，端点用 `anchorPoint()` 把局部点按元素 rotation 绕中心旋转回世界坐标（翻转不影响矩形边界，不用处理）。
  - 线型三种：`straight` 直线 / `curve` 三次贝塞尔（`bend = clamp(dist*0.4, 30, 160)`，控制点沿两端法线外推）/ `elbow` 正交折线（按长短轴决定先横后竖）。
    箭头三角形是**自己算的多边形**（`arrowTriangle()`），没用 SVG `marker`——marker 的 `fill` 不能可靠继承 `context-stroke`，自己画颜色可控。
  - 渲染在**世界层里的一个 SVG** 里，`viewBox` 直接取「所有连线两端元素的外框并集 + padding」，于是 path 的 `d` 可以用世界坐标原样写，
    线宽/箭头/连接点大小一律除以 `zoom`（屏幕尺寸恒定，和手柄一个套路）。
  - 命中测试：每条线再画一条 `stroke: transparent`、`stroke-width: 16/zoom`、`pointer-events: stroke` 的粗线，带 `data-item-id`，于是既有的「点选/右键菜单」逻辑直接复用。
  - 「线上文字」复用元素文字的编辑流程：`text` 字段 + 双击进编辑，只是编辑框定位到线的中点（`geometry.label`）。
  - **删元素要连带删线**：`softDelete()` 会把 `connectedEdges()` 一起标删（同一批 patch、同一条撤销记录），否则会留下悬空的线。
  - Ctrl+D 复制连线时把端点**重映射到副本**（`idMap`），端点没一起复制的保持原指向。
  - 连线不参与框选、对齐、微调、分组归属（`itemsInRect()`、`align()`、`nudge()`、`adoptIntoFrames()` 都显式排除 `edge`）。

## 图片链路（复用笔记那套 OSS 直传，多了目录白名单）

- 走 `canvas/` 前缀直传 OSS，**不占 N1 eMMC**；`crop`/`flip`/`rotation` 都只是渲染参数，不产生新对象。
- 只有「任一边 > 2560px 或文件 > 6MB」才压到长边 2560（PNG/WebP 输出 PNG 保透明，GIF/SVG 原样传），
  与笔记的 1600px 策略分开（`shrinkForCanvas` vs `shrinkIfNeeded`）。
- 图片在画布里的初始长边上限 800 世界像素（`IMAGE_MAX_EDGE`），避免一张大图糊满屏幕。
- **同一张图允许多个元素共用一个 OSS key**（Ctrl+D 复制、复制画布都会复用对象），
  所以回收前必须 `recycleUnreferenced()` 查一遍引用：还有元素在用的 key 一个都不删；查询失败时**保守全留**。
- 粘贴 / 拖文件 / 拖网页图片链接（服务端转存，见 [oss-images.md](oss-images.md)）三个入口都在 `CanvasStage.vue`。
  **粘贴只有键盘 `Ctrl+V` 这条入口**：右键菜单里的「粘贴图片」已于 2026-10-14 删除——它走 `navigator.clipboard.read()`，
  浏览器在没有权限/非用户手势时只回一句「浏览器不允许直接读剪贴板」，还不如直接 `Ctrl+V`（`onPaste` 读 `clipboardData.items`，不需要权限）。
  别把那条菜单项加回来，也不要替它加权限弹窗（`navigator.permissions` 在 Chrome 里对 clipboard-read 静默失败）。

## 粘贴链接：是图片就转存，不是图片就贴成链接卡片（2026-10-14）

粘贴（`Ctrl+V`）或从网页拖入一个 `http(s)://` 地址时，**先让服务端验一下这是什么**，再决定放成什么：

```
粘贴/拖入地址 → POST /api/oss/fetch（钩子先 HEAD 探 Content-Type）
   ├─ image/*      → 抓字节 → 直传 OSS → 图片元素（老行为，一点没变）
   ├─ 非图片        → 钩子回 400「目标不是图片：text/html; charset=utf-8」
   │                 → 前端识别成 RemoteUrlNotImageError → addLink() 贴成链接卡片
   └─ 真失败（404/超时/超大）→ 照旧报错，弹「链接处理失败：…」
```

要点：

- **判断依据是服务端探到的类型，不是文件后缀**，所以 `github.com/xx` 这种页面地址不会被当成图片去下载。前端 `api/oss.ts`
  里 `fetchRemoteImage()` 把「目标不是图片」这条文案翻成 `RemoteUrlNotImageError`（`isNotImageUrlError()` 判类型，别用 `instanceof` 跨层判），
  `store.addRemoteUrl()` 捕获后就地 `addLink()`，并返回 `'image' | 'link' | 'error'` 让 `CanvasStage.addWebUrl()` 决定提示文案
  （「不是图片，已作为链接贴入画布」）。**这条判断依赖钩子的报错文案**，钩子里改文案的话这里的匹配常量要一起改。
- 链接卡片：`kind='link'`，地址存 **`source_url`**（和图片的原始地址同一个字段），`text` 留作自定义标题（有值时卡片标题用它）。
  默认 320×76，渲染成「🔗 + 域名 + 路径 + ↗」的小卡片（`CanvasItemView` 的 `canvas-item__link`），长地址省略号截断、`title` 悬停看全文。
- **打开方式**：选中卡片后点上方操作栏的「打开」，或点卡片右上角的 ↗，或右键「打开链接」。
  **双击卡片＝编辑链接**（标题 + 地址，见下面「编辑链接」），不是直接打开——2026-10-14 用户明确要的是可编辑。
- **编辑链接**：双击卡片 / 操作栏「编辑」/ 右键「编辑链接…」都打开同一个 `el-dialog`（两个输入框：标题、地址），
  保存时一次 patch `{ source_url, text }`（`text` 就是卡片标题，留空则只显示域名）。地址要过 `^https?://` 校验。
  复制走 `utils/link.ts` 的 `copyText()`——**内网是 http，`navigator.clipboard` 在非安全上下文里不存在**，
  必须退回 `document.execCommand('copy')`，否则用户在 8090 上永远复制不了。
- 拖入的网页地址同样走这条链路（`onDrop` 里图片文件优先，然后是 `extractUrl()` 拿到的地址）；两者都失败才提示「没有识别到图片或链接」。
- 卡片不抓页面标题/图标（那需要再开一个钩子路由 + 外网请求），要改标题就右键「改地址…」，或在 PB 里给 `text` 填个短标题。
- 链接卡片和图片/文字一样参与框选、拖动、缩放、分组、复制、软删除与撤销重做——它们只是 `kind` 多了一个值，没有额外分支。

## 撤销重做：拖拽中不写栈

拖拽的每一帧都调用 `store.setItemFields()`（只改内存 + 标脏），拖拽开始时用 `snapshotItems()` 存一份「拖前快照」，
指针抬起再 `commitGeometry(快照, '移动')` 生成**一条**撤销记录。否则一次拖动会塞进上百条历史。

撤销条目 = `{ label, created: [id...], changes: [{id, before, after}] }`：

- `created` 里的元素，撤销 = 软删除（对象保留，可重做恢复）；
- `changes` 存字段级 before/after，撤销反向应用、重做正向应用；
- 栈深 50，**只覆盖布局与内容**（移动/缩放/旋转/裁剪/翻转/层级/对齐/新增/删除/文字/分组），
  视口平移缩放与画布重命名不进栈。

细节坑：

- **编辑文字时要把元素本身藏起来**：`CanvasItemView` 的 `v-show` 条件里除了 `croppingId` 还要带上 `editingId`，
  否则编辑框后面会透出同一段旧文字（一块「影子文字」），而且两边折行宽度差几个像素，看着像重影。
  编辑时顺带把蓝色外框/手柄一起 `v-show="!editingId"` 收掉，画面里只留那个虚线编辑框。
- **弹窗打开时画布快捷键要让路，但别用 `.el-overlay` 判断**：布局里常年存在几个**隐藏的** overlay（抽屉、CRUD 弹窗），
  `document.querySelector('.el-overlay')` 恒为真，会把 Ctrl+0 / 空格平移 / 删除全部吞掉（踩过：适应窗口失效）。
  用显式的 `modalOpen` ref：`el-dialog` 的 `@open/@closed` 加 `ElMessageBox` 前后手动置位。
- **`click` / `dblclick` 的 `event.target` 会被指针捕获改写（2026-10-14 用户报「在文本上双击变成新建」的根因）**：
  任何走了 `setPointerCapture` 的手势（拖元素、连线、框选…）都会让 Chrome 把随后的**兼容鼠标事件一律改派到捕获元素**——
  也就是 stage 根节点。于是 `event.target` 不再是光标下的元素，`closest('[data-item-id]')` 永远是空，
  双击文字就落进「空白处新建文字」那条分支（看上去像「双击文本反而多出一个空文本框」）。
  正确写法是**按坐标自己找元素**：`document.elementFromPoint(event.clientX, event.clientY)`，
  和 `onPointerUp`（连线落点）、`showMenuAt`（右键菜单）同一套路。**以后凡是靠 `event.target` 判元素的鼠标事件都要这么写。**
- **双击的判定顺序**（`onDoubleClick`）：先用 `elementFromPoint` 拿元素，然后依次排除编辑框（`[data-text-editor]`，里面双击是选词）、
  缩放手柄（`[data-handle]`）、裁剪手柄、工具栏与右键菜单（这些位置上的双击不是「画布空白」），再看是不是元素、是哪种 `kind`。
- **`data-frame-bar` 打在分组框的根节点上**（不是标题栏那条），所以 `closest('[data-frame-bar]')` 对框内任何位置都成立——
  `onPointerDown` 里「框内空白当空白处理」那条判断因此永远不触发：**拖框的内部实际是拖动这个框**（Figma 那种手感），
  只有标题栏那 30px 是「标题栏」。双击用的是标题栏的类名（`.canvas-item__frame-bar`），于是框内双击＝新建文字、标题栏双击＝改名。
  想改成「框内拖动＝框选」的话，把 `data-frame-bar` 挪到 `.canvas-item__frame-bar` 上即可（同时会失去「拖框体移动分组」的手感，改前先问）。
- **新建元素自动归属分组**：`store.frameAt(中心点)` 在 `addText`/`addNode`/`addLink` 里按「中心点落在哪个框里」写好 `frame_id`
  （和拖动结束时的 `adoptIntoFrames()` 同一套规则），所以在框里双击新建的文字会跟着框一起走，不用先拖一下才认领。
- **四边手柄会被连接点圆点挡住（2026-10-14 修）**：圆点画在「两端中点」，和 n/w/e/s 四个缩放手柄完全重叠，而它们在 DOM 里更靠后、还带 `z-index:2`，
  于是 `pointerdown` 全被圆点抢走——表现就是**文本框只能拖角手柄整体缩放，左右边手柄像是不存在**（用户就是这么报的）。
  两条修正：① `anchorDotStyle()` 把圆点沿 `anchorNormal()` 往外挪 12 屏幕像素（`/zoom`，和手柄不再重叠，视觉上也更像节点编辑器的连接点）；
  ② `.canvas-stage__handle` 加 `z-index:3` 兜底。**挪圆点没有破坏连线**：连线手势仍然从圆点起手、终点判定也仍认 `[data-anchor]`，端点和线的起点仍按元素真实外框算。
- **文本框的「自动高度」靠一个探针元素量**（`utils/textMetrics.ts` 的 `textBoxHeight()`）：在 body 下挂一个 hidden div，
  `white-space:pre-wrap / overflow-wrap:anywhere / line-height:1.35` 与 `.canvas-item__text` 保持一致，量出来的就是世界坐标下的高度。
  拖左右边手柄时每帧量一次（不吃 Vue 的 nextTick，量的是最终布局）；**判空跳过**（空文字时返回 0，调用方按「不改高度」处理），
  编辑文字提交时是**只长不缩**（`fitted > h` 才写 h），免得把用户手动拉高过的框压回去。
- **字号只在「角手柄 + 没按 Shift」时缩放**（`uniformScale`），其它情况一律不动字号。别改回「(kx+ky)/2 一刀切」——
  那样拖边手柄也会顺带改字号，又变回「只能整体调整」。
- **元素 rotated 时的手柄**：缩放/裁剪的世界位移要按 `-rotation` 旋转到元素自身坐标系（`localDelta()`），否则旋转过的图拖手柄会「斜着跑」。
- **翻转要作用在整个元素上**（外框 transform 里 `scaleX/scaleY`），不能只翻 `<img>`：裁剪后 img 比外框大且带偏移，翻 img 会翻错轴。
- **裁剪语义**：`crop` 是相对原图的归一化区域，裁剪浮层显示的是**整张原图**（`sourceRectOf()` 给出原图在元素坐标系里的位置），
  所以可以往外拖把裁掉的区域补回来。点「确认」时 `cropFromLocalRect()` 会**同时给出新外框**——
  外框必须跟着裁剪框平移（`x/y` 一起改），否则「从左边裁掉一块」会把剩下的画面整体左移。
- **对齐吸附**阈值是 `6 / zoom`（屏幕像素恒定），拖动时按选区外框与其它元素的边缘/中线比对，`Alt` 临时关掉吸附。
- **原生拖拽会掐断指针手势（踩过）**：鼠标从元素移到图片上时，Chrome 会启动 HTML5 图片拖拽，紧接着对进行中的指针手势发出
  **`pointercancel`**（表现：拖到一半就断了，只有第一小步生效）。所以画布根节点上必须有 `@dragstart.prevent`，
  元素与裁剪浮层里的 `<img>` 一律 `draggable="false"`；`.canvas-stage` 上还要 `touch-action: none`。
- **别让新画布排在最后就找不到**：新建画布 `sort` 取 max+1，会排在列表末尾，而 `init()` 原来只打开 `canvases[0]`，
  于是刷新后会跳到另一块板。现在用 `localStorage.pb_canvas_last` 记住上次打开的板（不存在才退回首块）。
- **连接点要在裁剪/编辑文字时藏起来（踩过）**：连接点圆点渲染在裁剪手柄同一位置、且 DOM 更靠后，会抢走裁剪手柄的 pointerdown
  （表现：进裁剪模式后拖手柄没反应、外框不变）。`anchorHost` 在 `croppingId`/`editingId` 有值时直接返回 null。
- **悬停状态别被连接点自己打断**：指针移到圆点上时 `closest('[data-item-id]')` 是空的（圆点是元素外的兄弟节点），
  会把 `hoveredId` 清掉、圆点当场消失，连线手势也就起不来。两条修正：`onPointerOver` 里把 `data-anchor-item` 也当作悬停目标；
  连线手势进行中（`connectState`）不改悬停目标、并把连接点固定在起点元素上。

## 元素不要有合成层提示（2026-10-15：修「链接卡片/文字发虚」）

**症状**：画布放大到 177%（= 六次 1.1 倍滚轮）时，链接卡片（以及文字、流程节点这些「元素」）的文字和边框发虚，
而**画在世界层里的连线、网格是清楚的**。缩回 100% 又正常。

**怎么定位的**（值得复用的一套办法）：把用户截图和本机正常截图做像素级对比——取文字笔画上相邻像素的最大亮度阶跃，
用户截图是 87.6，本机正常渲染是 154~166；再把本机截图的卡片按 1/1.77 降采样再放大回原尺寸，阶跃变成 98，
和用户截图对上了。也就是说：**元素内容是按 1:1（世界坐标）光栅化后，被合成器放大 1.77 倍的**，
而世界层自己的 transform 带 zoom，所以它栅格化是对的（连线和网格清楚就是证据）。

**原因**：`.canvas-item` 原来挂着 `will-change: transform`（并且 wrapper 上永远写着
`rotate(0deg) scaleX(1) scaleY(1)` 这种恒等 transform）。这两样都会让浏览器把**每个元素**提升成独立合成层；
这类层的栅格分辨率是按「**层自己** transform 的缩放」算的（恒等 = 1），而不是按父级世界层的 zoom。
于是在画布 zoom=1.77 时，元素贴图被 1.77 倍放大 → 文字、边框发虚。

**修法**（别再改回去）：

- `.canvas-item` **不加** `will-change`（也别加 `translateZ(0)`、`backface-visibility: hidden` 之类的提升技巧）；
- `wrapperStyle` 只在真的有旋转/翻转时才写 `transform`，没有就写 `none`——**不要写恒等值**，同样会触发提升；
- 元素内容于是直接画进世界层，跟着世界层的栅格分辨率走（世界层的 `will-change: transform` 要留着，平移才顺）。

**注意**：本机 Chrome 113 / 155、Edge 155 都**不会**复现（它们会正确地重新光栅化被缩放的层），
所以改完在开发机上看不出差别，只能靠上面的机制推理 + 用户端确认。
代价是拖拽时元素内容会被画进世界层、按外框面积重绘（小板上无感）；
真出现大板拖拽掉帧，再考虑「只在手势期间加合成层提示」，但手势结束必须移除，否则模糊会回来。

## 保存策略

- 元素：改动标脏（`dirtyIds`，模块级 `Set` 不参与响应式），300ms debounce 后逐条 PATCH 变化过的元素；
  失败重新标脏并保留本地数据，工具栏显示错误 + 「重试」，**不吞错也不清空界面**。
- 画布级（viewport/标题/主题）：500ms debounce。
- 强制落盘：切画布、组件卸载、`beforeunload`（有未保存项时拦截提醒）。
- 工具栏的 `:loading` 之类不能用「保存中」当条件——按钮会被连带禁用（笔记模块踩过同一个坑），这里只用文字状态。

## 删除语义（与随手笔记一致）

删除元素 = `deleted=true`（图片还在 OSS），画布侧栏「最近删除」可恢复或彻底删除（链接卡片也在这张列表里，标签是「链接 <域名/路径>」）；
**只有彻底删除**（单个元素、清空本画布回收站、彻底删除整块画布）才调 `POST /api/oss/delete` 回收对象，回收前查引用。
删除整块画布也是软删除（`trashed`），彻底删除时才连带删掉它的元素记录。

## 已知边界

- 元素上限 2000（`ITEM_LIMIT`，一次 `listAll` 拉完当前画布）；超了界面会提示拆板。
- 链接卡片只存地址，不抓标题/图标/摘要；也不做「点开前预览」。
- 单人使用、服务端存储即多设备同步，最后写入者胜，不做并发合并。
- 不做导出 PNG、演示模式、网格吸附。
- 画布内不做跨板共享素材库（从笔记复用图片也没做），但复制元素/复制画布会复用同一批 OSS 对象。

## 实测性能（2026-10-13，本机 Chrome 无头 + 真机）

200 个元素（复用同一个 OSS 对象、20×10 网格）：

| 指标 | 结果 |
| --- | --- |
| 世界层 DOM 节点 | 400（每张图 = 外层 div + img） |
| 元素挂载（骨架出现） | 274ms |
| 图片全部加载完 | 586ms |
| 拖动 30 步指针移动 | 501ms（约 17ms/步，跟手） |
| Ctrl+A 全选 200 项 | 11ms |
| 进板自动「适应全部」 | zoom 0.23（把整块板收进视口） |

结论：几百张图这个量级，DOM + CSS transform 的路子完全够用，不必上 Canvas 2D。
